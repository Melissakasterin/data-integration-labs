# Open-Source Project Analysis: pandas

## 1. Project Overview

- **Project:** pandas
- **GitHub repository:** https://github.com/pandas-dev/pandas
- **Purpose:** pandas is a Python library for data manipulation and analysis.

## 2. License
### GitHub API comparison

- **pandas-dev/pandas:** The API reports the `spdx_id` `BSD-3-Clause`, because GitHub recognised the licence file as the BSD 3-Clause licence.
- **Melissakasterin/data-integration-labs:** The API reports the `spdx_id` `MIT`, because GitHub recognised my `LICENSE` file as the MIT License.
- **owid/co2-data:** The API returns `"license": null`, which means that GitHub found no licence file it could read, although licence information can still exist elsewhere in the project.

**API sources:** [pandas](https://api.github.com/repos/pandas-dev/pandas), [my repository](https://api.github.com/repos/Melissakasterin/data-integration-labs), [OWID CO₂ data](https://api.github.com/repos/owid/co2-data)

The pandas project has all four requested community files. GitHub lists them under [Community standards](https://github.com/pandas-dev/pandas/community).

- **README:** Describes the project. [README.md](https://github.com/pandas-dev/pandas/blob/main/README.md)

These files help contributors understand the project's rules and how to participate responsibly.

## 7. Contribution Guide

The pandas project welcomes contributions from developers of all experience levels.

- **Finding tasks:** Beginners can look for suitable issues, including issues labeled `good first issue` and `Docs`.
- **Reporting bugs:** Bug reports and enhancement requests should be submitted through GitHub Issues.
- **Submitting changes:** Contributors use Git and GitHub, create a fork, make changes and submit a Pull Request for review.
- **Review process:** Maintainers review proposed changes before they are merged.
- **Source:** [Official pandas Contributing Guide](https://pandas.pydata.org/docs/development/contributing.html)
